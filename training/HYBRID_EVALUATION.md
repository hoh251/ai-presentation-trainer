# ทดลองใช้ v2 ตรวจนอกเรื่อง และ v4 ตรวจความครอบคลุม

วันที่ 4 พฤศจิกายน 2569 — ผลทดลองออฟไลน์ ยังไม่เปลี่ยนโมเดลใน `model_package`

## คำตอบสั้น

หากต้องเลือก **แนวทางที่จับประเด็นได้ดีขึ้นโดยรักษาความสามารถแยกนอกเรื่อง** จากตัวเลือกที่ทดสอบ ให้ทดลองระบบสองด่าน: `v2 off-topic gate → v4 coverage scorer` แต่ยังไม่ควรแทน v2 ในระบบที่ใช้จริงทันที เพราะความผิดพลาดแบบชมว่า “ครบ” ทั้งที่ไม่ครบเพิ่มขึ้น และข้อมูลทดสอบทั้งหมดเป็นคำตอบสังเคราะห์ที่ผู้พัฒนาสร้าง/ติดป้ายเอง

ด่านแรกใช้คะแนนสูงสุดของ v2 จากทุกเกณฑ์ของคำถามเดียวกันเพื่อตัดสินว่านอกเรื่องหรือไม่ ถ้านอกเรื่องให้ทุกเกณฑ์เป็น `missing`; ถ้าไม่ใช่ ให้ใช้ v4 ตัดสิน `missing/partial/covered` ของแต่ละเกณฑ์ **ใช้ threshold ที่คาลิเบรตจาก validation ก่อนการทดลองนี้** ไม่ปรับ threshold ให้เข้ากับ test หรือชุด 50 กรณี

| วิธี | Validation 98 เกณฑ์: coverage F1 / off-topic F1 ระดับคำตอบ / ชมผิด | Test สังเคราะห์ 86 เกณฑ์ | ชุด 50 กรณีเดิม (diagnostic) |
|---|---|---|---|
| v2 ทั้งสองงาน | 0.690 / 0.941 / 0.015 | 0.659 / 1.000 / 0.017 | 0.420 / 0.947 / 0 |
| v4 ทั้งสองงาน | 0.732 / 0.875 / 0 | 0.705 / 0.882 / 0.033 | 0.485 / 0.706 / 0.019 |
| **v2 นอกเรื่อง + v4 ครอบคลุม** | **0.732 / 0.941 / 0** | **0.705 / 1.000 / 0.033** | **0.485 / 0.947 / 0.019** |
| วิธีข้างบน แต่ต้องให้ v2 ยืนยันก่อนตอบว่า `covered` | 0.693 / 0.941 / 0 | 0.695 / 1.000 / 0.017 | 0.406 / 0.947 / 0 |

`coverage F1` คือ macro F1 ของสามสถานะ; `ชมผิด` คือสัดส่วนเกณฑ์ที่ระบบให้ `covered` ทั้งที่ป้ายจริงไม่ใช่ `covered` หรือเป็นคำตอบนอกเรื่อง ตัวอย่าง test สังเคราะห์: v2 ชมผิด 1 เกณฑ์ ส่วนวิธีสองด่านชมผิด 2 เกณฑ์ จากเกณฑ์ที่ไม่ควรได้ `covered` 60 เกณฑ์ ชุด 50 กรณีเดิม: v2 0/53, วิธีสองด่าน 1/53

**ข้อจำกัดของการเปรียบเทียบ:** ชุด 50 และ test สังเคราะห์ถูกเปิดดูผลจากการทดลองก่อนหน้าแล้ว จึงใช้เป็นตัวชี้ปัญหา ไม่ใช่ holdout อิสระหรือหลักฐานว่าระบบสองด่านจะดีกับคำตอบนักศึกษาจริง ค่า off-topic ในตารางนี้คำนวณระดับคำตอบโดยรวมคะแนนทุกเกณฑ์ของคำถามเดียวกัน ซึ่งต่างจากตารางก่อนหน้าที่บางช่องคำนวณระดับแถวเกณฑ์

## คำตัดสินและงานต่อ

1. คง v2 เป็น package ที่ Backend ใช้จริงอยู่ในขณะนี้ จนกว่าจะมีข้อมูลใหม่สำหรับยืนยันผลและตกลงสัญญาร่วมกับ Backend
2. เก็บ `v2 → v4` เป็นตัวเลือกทดลองที่ **ดีกว่า v2 ด้าน coverage บนชุดทดสอบที่มี** โดยไม่เสีย off-topic ในชุดเดียวกัน แต่ต้องลด false-covered ก่อนใช้งานจริง
3. วิธีให้ v2 ยืนยัน `covered` ลด false-covered ได้ แต่ทำให้คำตอบที่ครบจริงหลายข้อกลายเป็น `partial`; ไม่เลือกเป็นคำตอบสุดท้าย
4. เก็บคำตอบจริงจาก PDF หลายหัวข้อ ให้คนอย่างน้อยสองคนตรวจป้ายตาม rubric โดยเฉพาะคู่คำตอบ `partial/covered`, คำปฏิเสธ และคำตอบกวน จากนั้นกันหัวข้อและผู้ตอบบางส่วนไว้ทดสอบครั้งสุดท้ายโดยไม่ใช้ปรับ threshold
5. หากผลใหม่ยืนยันแนวทางสองด่าน ค่อยออก `model_version` และ manifest ใหม่ ทดสอบเวลาตอบสนอง/หน่วยความจำบนเครื่องที่จะเสิร์ฟจริง และให้ Backend รองรับสอง checkpoint ตามสัญญากลางก่อนสลับระบบ การทดลองนี้โหลดสองรุ่นทีละรุ่นเพื่อวัดคะแนน ยังไม่ได้ทดสอบการโหลดพร้อมกันหรือเวลาตอบหนึ่งคำถามบนเครื่องเสิร์ฟ

ผลตัวเลขแบบละเอียดอยู่ใน [`optimization/hybrid_v2_v4.json`](optimization/hybrid_v2_v4.json) ทำซ้ำด้วย [`evaluate_hybrid_v2_v4.py`](evaluate_hybrid_v2_v4.py) โดยต้องมีโมเดลฐานและ checkpoint ที่เก็บนอก Git

## แหล่งวิจัยที่ใช้กำหนดขั้นถัดไป

- [Boonsarngsuk et al., SEALP 2025](https://aclanthology.org/2025.sealp-1.3/) ศึกษาการเลือกตัวอย่างสำหรับให้คะแนนคำตอบสั้นในบริบทไทย สนับสนุนการคัดคำตอบจริงที่หลากหลายมาติดป้าย
- [Vahtola et al., SemAntoNeg 2022](https://aclanthology.org/2022.blackboxnlp-1.20/) แสดงข้อจำกัดของ embedding ต่อคำปฏิเสธ/คำตรงข้าม จึงต้องทดสอบคู่คำตอบที่ต่างกันเพียงคำสำคัญ
- [Bates et al., Conformal Risk Control 2024](https://research.google/pubs/conformal-risk-control/) ให้แนวคิดคุมความเสี่ยงด้วยชุด calibration; ข้อมูลสังเคราะห์ของเรายังไม่รองรับการอ้างหลักประกันแบบนั้น
