# วิธีเก็บคำตอบจาก PDF หัวข้อใหม่เพื่อฝึกและประเมินโมเดล

## หลักการ

- หนึ่งแถว = คำถามหลักหนึ่งข้อ + เกณฑ์หนึ่งข้อ + คำตอบหนึ่งครั้ง; ถ้าคำถามมี 2 เกณฑ์ให้ติดป้าย 2 แถวแยกกัน
- เก็บ `deck_id`, ชื่อ/แฮช PDF, `source_page`, `question`, `current_prompt`, `criterion_id`, `criterion`, `evidence_quote` หรือ visual evidence ที่ตรวจแล้ว, `answer`
- คน A และคน B ติดป้ายโดยไม่เห็นป้ายของกันและกัน: `covered`, `partial`, `missing` และ `off_topic=true/false`; กรณีไม่ตรงกันให้บันทึกเหตุผลและตัดสินร่วมกันก่อนนำไปฝึกหรือทดสอบ
- `covered`: คำตอบให้สาระของเกณฑ์ครบ แม้ใช้คำพ้อง/ภาษาพูด; `partial`: เกี่ยวข้องแต่ขาดองค์ประกอบสำคัญ; `missing`: ไม่กล่าวหรือกล่าวผิด/ปฏิเสธประเด็น; `off_topic`: ไม่ตอบ prompt ปัจจุบันเลย
- อย่าดูผลของโมเดลก่อนลงป้าย และอย่าคัดลอกคำตอบจากสไลด์เป็นคำตอบส่วนใหญ่ ต้องมีคำตอบมนุษย์จริงหรือคำตอบที่คนเขียนอย่างเป็นอิสระ
- แบ่ง train/validation/test **ตาม PDF** ก่อนฝึก; PDF ที่ใช้เลือก model/threshold ไม่ใช่ holdout อีกต่อไป; Deadlocks 100 และชุด 50 เดิมเป็น diagnostic ที่เปิดผลแล้ว
- ทำตารางผลต่อ PDF เพื่อเห็น distribution shift ไม่ดูแค่ค่าเฉลี่ยรวม

## ชุดตรวจที่ต้องมี

- คำตอบถูกแบบสั้น, ถูกแบบยาว, คำพ้อง, ภาษาพูด/คำแสลง, ไทยปนอังกฤษ, คำผิด
- ถูกบางส่วน, ถูกหนึ่งเกณฑ์ผิดอีกเกณฑ์, คำสำคัญตรงแต่ใจความผิด, คำปฏิเสธ, ข้อมูลขัดสไลด์
- ไม่รู้, คำมั่ว, คำด่า, เปลี่ยนเรื่อง, คำสั่งหลอกระบบ
- PDF ใหม่ที่เป็นข้อความ, ภาพ, flow และตาราง; กรณีภาพต้องมีหลักฐานที่คนตรวจย้อนกลับไปดูได้

## สิ่งที่ต้องรายงานเมื่อทดลอง candidate

Coverage precision/recall/F1 ราย `covered/partial/missing`, macro F1, off-topic F1, false-covered rate, confusion matrix, จำนวนคำตอบที่ขอให้ตอบเพิ่ม และตัวอย่างที่ผิด ชุดทดสอบที่เปิดผลก่อนเลือกวิธีห้ามใช้เป็นหลักฐานว่า candidate ใหม่ generalize ได้
